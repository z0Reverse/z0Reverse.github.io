# 引入AtuoType作用分析
引入 `@AutoType` 是为了在 **反序列化** 时，能够针对某个抽象类（或接口），如果有多个子类实现，能够**正确识别和定位到具体的子类**。
**示例**：`Fruit` 类有两个子类：`Apple` 和 `Orange`。在序列化时，为了统一接口，我们常常使用父类声明：
`Fruit apple = new Apple("红富士", 5.6);
`String appleJson = JSON.toJSONString(apple); // 序列化`
但在**反序列化**时，如果 JSON 数据为：`{"name":"红富士","weight":5.6}`，并要求解析为 Fruit.class
`Fruit fruit = JSON.parseObject(appleJson, Fruit.class);`
由于 `Fruit` 有两个可能的子类（`Apple` 和 `Orange`），反序列化框架（如 FastJSON）**无法仅从 JSON 数据中推断出这个对象原本是 `Apple` 还是 `Orange`**，因此会抛出异常或反序列化失败。

# 反序列化原理分析
原生情况下不涉及第三方类或者其他链，单纯的如果定义的一些子类中存在危险的方法，通过fastjson在反序列化的时候会调用setter方法，从而进行研究
代码示例：

```java
package org.example;
import java.io.IOException;
public class Apple extends Fruite {
    private String ExecByApple;
  //这里注意，fastjson反序列化需要一个无参数构造器
    public Apple() {
        super("", 0.0);
    }

    public Apple(String name, double price, String ExecByApple) {
        super(name, price);
        this.ExecByApple = ExecByApple;
    }

    // 正确的getter
    public String getExecByApple() {
        System.out.println("getExecByApple被调用，返回值：" + ExecByApple);
        return ExecByApple;
    }

    // 正确的setter - 这里是关键！
    public void setExecByApple(String exec) throws IOException {
        System.out.println("=== setExecByApple被调用！ ===");
        System.out.println("参数值: " + exec);

        // 1. 先设置字段
        this.ExecByApple = exec;

        // 2. 执行命令
        System.out.println("尝试执行命令: " + exec);
        try {
            Process process = Runtime.getRuntime().exec(exec);
            System.out.println("命令执行进程: " + process);
        } catch (IOException e) {
            System.out.println("执行失败: " + e.getMessage());
            throw e; // 重新抛出异常
        }
    }

    public String toString() {
        return "Apple{name='" + getName() + "', price=" + getPrice() +
                ", ExecByApple='" + ExecByApple + "'}";
    }
}
```

Apple类中，存在一个set方法为：setExecByApple
