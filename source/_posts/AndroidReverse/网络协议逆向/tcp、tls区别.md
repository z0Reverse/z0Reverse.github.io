# TCP和TLS区别

## **1. 标准 TCP 的三次握手和四次挥手**

### **1.1 三次握手（建立连接）**
1. **客户端 → 服务器**：发送 SYN 报文，请求建立连接。
2. **服务器 → 客户端**：发送 SYN-ACK 报文，确认客户端的请求。
3. **客户端 → 服务器**：发送 ACK 报文，确认服务器的响应。

### **1.2 四次挥手（终止连接）**
1. **客户端 → 服务器**：发送 FIN 报文，请求关闭连接。
2. **服务器 → 客户端**：发送 ACK 报文，确认客户端的请求。
3. **服务器 → 客户端**：发送 FIN 报文，请求关闭连接。
4. **客户端 → 服务器**：发送 ACK 报文，确认服务器的请求。

## **2. 单向认证的 TLS/SSL 握手**

在单向认证中，只有服务器向客户端提供证书，客户端验证服务器的身份。

### **2.1 握手过程**
1. **客户端 → 服务器**：发送 ClientHello，包含支持的 TLS 版本、加密套件和随机数。
2. **服务器 → 客户端**：发送 ServerHello，选择 TLS 版本和加密套件，并发送服务器的随机数。
   - 发送服务器的证书（包含公钥）。
   - 发送 ServerHelloDone，表示服务器信息发送完毕。
3. **客户端 → 服务器**：
   - 验证服务器的证书。
   - 生成预主密钥（Pre-Master Secret），使用服务器的公钥加密后发送给服务器。
   - 发送 ChangeCipherSpec，表示后续通信使用协商的加密套件。
   - 发送 Finished，验证握手过程是否成功。
4. **服务器 → 客户端**：
   - 使用私钥解密预主密钥，生成主密钥（Master Secret）。
   - 发送 ChangeCipherSpec，表示后续通信使用协商的加密套件。
   - 发送 Finished，验证握手过程是否成功。

### **2.2 四次挥手**
与标准 TCP 的四次挥手相同。

## **3. 双向认证的 TLS/SSL 握手**

在双向认证中，服务器和客户端都需要提供证书，双方验证彼此的身份。

### **3.1 握手过程**
1. **客户端 → 服务器**：发送 ClientHello，包含支持的 TLS 版本、加密套件和随机数。
2. **服务器 → 客户端**：发送 ServerHello，选择 TLS 版本和加密套件，并发送服务器的随机数。
   - 发送服务器的证书（包含公钥）。
   - 发送 CertificateRequest，请求客户端提供证书。
   - 发送 ServerHelloDone，表示服务器信息发送完毕。
3. **客户端 → 服务器**：
   - 验证服务器的证书。
   - 发送客户端的证书（包含公钥）。
   - 生成预主密钥（Pre-Master Secret），使用服务器的公钥加密后发送给服务器。
   - 发送 CertificateVerify，使用客户端的私钥对握手消息进行签名，证明客户端拥有私钥。
   - 发送 ChangeCipherSpec，表示后续通信使用协商的加密套件。
   - 发送 Finished，验证握手过程是否成功。
4. **服务器 → 客户端**：
   - 验证客户端的证书。
   - 使用私钥解密预主密钥，生成主密钥（Master Secret）。
   - 发送 ChangeCipherSpec，表示后续通信使用协商的加密套件。
   - 发送 Finished，验证握手过程是否成功。

### **3.2 四次挥手**
与标准 TCP 的四次挥手相同。
